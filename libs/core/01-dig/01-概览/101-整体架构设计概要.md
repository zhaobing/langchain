# LangChain-Core 整体架构设计概要

## 项目概述

`langchain-core` 是 LangChain 生态系统的**基础抽象层**。它定义了所有其他 LangChain 包所构建的**基础接口、协议和原语**。该包遵循以 Runnable 协议为中心抽象的**分层架构**，其他所有组件都围绕它构建。

## 核心架构原则

1. **Runnable 协议** - 所有组件的统一接口
2. **Pydantic 集成** - 所有主要类继承自 `BaseModel` 以进行验证和序列化
3. **异步/同步并行** - 所有操作同时支持同步和异步变体
4. **LCEL（LangChain 表达式语言）** - 使用 `|` 运算符进行声明式组合
5. **配置传播** - `RunnableConfig` 在整个链中流动
6. **序列化系统** - `Serializable` 基类用于安全的对象持久化

## 模块详细分析

### 1. **runnables/** - 核心抽象层

**功能**: 为所有 LangChain 组件提供统一接口。

**关键类**:
- **`Runnable[Input, Output]`** (base.py) - 所有组件的抽象基类
  - 核心方法: `invoke()`, `batch()`, `stream()`, `ainvoke()`, `abatch()`, `astream()`
  - 通过 `|` 运算符支持组合 (LCEL)
  - 自动批处理、流式传输和异步支持

- **`RunnableSequence`** - 通过 `|` 链接 runnables
- **`RunnableParallel`** - 并行运行多个 runnables
- **`RunnablePassthrough`** - 传递输入并可选择添加键
- **`RunnableLambda`** - 将任意函数包装为 runnable
- **`RunnableBranch`** - 基于输入的条件路由
- **`RunnableWithFallbacks`** - 带有后备机制的错误处理
- **`RunnableWithMessageHistory`** - 管理对话历史

**配置管理** (config.py):
- **`RunnableConfig`** - 在链中传递的运行时配置
  - `tags`: 用于过滤调用
  - `metadata`: JSON 可序列化数据
  - `callbacks`: 事件处理器
  - `configurable`: 动态行为的运行时值
  - `run_id`: 追踪的唯一标识符

**与其他模块的关系**: 所有其他主要抽象（模型、工具、提示词、检索器）都继承自 `Runnable`，使其成为整个生态系统的基础。

### 2. **language_models/** - 语言模型接口

**功能**: 为所有语言模型实现提供抽象基类。

**关键类**:
- **`BaseLanguageModel[Input, Output]`** (base.py)
  - 继承 `RunnableSerializable`
  - 所有语言模型的根抽象
  - 支持缓存、回调、标签、元数据

- **`BaseChatModel`** (chat_models.py)
  - 用于基于聊天的模型（消息输入 → 消息输出）
  - 处理消息格式化和工具调用
  - 大多数现代实现使用此接口

- **`BaseLLM`** (llms.py)
  - 传统的字符串输入/字符串输出模型
  - 较旧的抽象，仍受支持

**类型定义**:
- `LanguageModelInput` = `PromptValue | str | Sequence[MessageLikeRepresentation]`
- `LanguageModelOutput` = `BaseMessage | str`

**关系**:
- 继承自 `Runnable`
- 使用 `messages/` 进行输入/输出
- 使用 `callbacks/` 进行可观测性
- 使用 `caches.py` 进行缓存

### 3. **messages/** - 消息系统

**功能**: 用于 LLM I/O 的丰富的多模态消息系统。

**核心类**:
- **`BaseMessage`** (base.py) - 所有消息类型的基础
  - `content`: `str | list[str | dict]` (支持多模态)
  - `additional_kwargs`: 提供者特定数据（工具调用等）
  - `response_metadata`: 标头、token 计数、模型信息
  - `name`, `id`: 可选标识符

**消息类型**:
- **`HumanMessage`** (human.py) - 用户消息
- **`AIMessage`** (ai.py) - 模型响应（包括工具调用）
- **`SystemMessage`** (system.py) - 系统指令
- **`ToolMessage`** (tool.py) - 工具执行结果
- **`FunctionMessage`** (function.py) - 传统函数调用
- **`ChatMessage`** (chat.py) - 带角色的通用消息

**内容系统** (content.py):
用于多模态数据的标准化**内容块**:
- `TextContentBlock` - 纯文本
- `ImageContentBlock` - 图像（URL 或 base64）
- `AudioContentBlock` - 音频数据
- `VideoContentBlock` - 视频数据
- `FileContentBlock` - 通用文件（PDF 等）
- `ReasoningContentBlock` - 模型推理/思考
- `ToolCall` - 函数调用请求
- `Citation` - 源文档引用

**块转换器** (block_translators/):
提供者特定的格式适配器:
- `openai.py` - OpenAI API 格式
- `anthropic.py` - Anthropic/Claude 格式
- `google_genai.py` - Google Gemini 格式
- `bedrock.py` - AWS Bedrock 格式
- 等

**关系**:
- 被 `language_models/` 用于模型 I/O
- 被 `prompts/` 用于模板输入
- 通过 `load/serializable.py` 序列化

### 4. **tools/** - 工具抽象

**功能**: 为 agents 使用的工具提供接口。

**关键类**:
- **`BaseTool`** (base.py)
  - 继承 `RunnableSerializable`
  - 表示 agent 可以调用的函数
  - 具有描述、args_schema、return_direct

- **`StructuredTool`** (structured.py) - 带有复杂参数模式的工具
- **`Tool`** (simple.py) - 基于简单函数的工具
- **`BaseToolkit`** - 相关工具的集合

**关键函数**:
- **`tool` 装饰器** (convert.py) - 将函数转换为工具
- **`convert_runnable_to_tool()`** - 将 runnables 转换为工具
- **`create_retriever_tool()`** - 从检索器创建检索工具

**工具模式**:
- 参数从函数签名推断
- 使用 Pydantic 模型进行验证
- 支持注入参数（run_manager、callbacks）

**关系**:
- 继承自 `Runnable`
- 使用 `messages/` 进行工具调用/结果
- 返回 `ToolMessage` 实例
- 可以将任何 `Runnable` 包装为工具

### 5. **prompts/** - 提示词模板

**功能**: 用于构建模型输入的灵活模板系统。

**关键类**:
- **`BasePromptTemplate`** (base.py)
  - 继承 `RunnableSerializable[dict, PromptValue]`
  - 带验证的输入变量
  - 用于预填充的部分变量
  - 可选的输出解析器

**模板类型**:
- **`PromptTemplate`** (prompt.py) - 基于字符串的模板
- **`ChatPromptTemplate`** (chat.py) - 基于消息的模板
  - `MessagesPlaceholder` - 用于动态消息列表
  - 特定角色的模板（Human、System、AI）
- **`FewShotPromptTemplate`** (few_shot.py) - 少样本学习提示词
- **`DictPromptTemplate`** (dict.py) - 字典输出

**特性**:
- 变量验证和类型检查
- Jinja2 支持 (jinja2_formatter)
- 部分变量填充
- 与输出解析器的管道组合

**关系**:
- 继承自 `Runnable`
- 使用 `messages/` 进行聊天模板
- 使用 `output_parsers/` 进行结构化输出
- 为 `language_models/` 格式化输入

### 6. **output_parsers/** - 输出解析器

**功能**: 从模型响应解析结构化输出。

**关键类**:
- **`BaseOutputParser[T]`** (base.py)
  - 继承 `RunnableSerializable[LanguageModelOutput, T]`
  - 方法: `parse()`, `parse_result()`, `get_format_instructions()`

**具体解析器**:
- **`StrOutputParser`** (string.py) - 解析为字符串
- **`JsonOutputParser`** (json.py) - 解析为 JSON/dict
- **`PydanticOutputParser`** (pydantic.py) - 解析为 Pydantic 模型
- **`ListOutputParser`** (list.py) - 解析为列表
- **`XMLOutputParser`** (xml.py) - 解析 XML

**关系**:
- 继承自 `Runnable`
- 与 `prompts/` 在链中一起使用
- 处理 `language_models/` 输出
- 返回结构化数据类型

### 7. **callbacks/** - 事件系统

**功能**: 执行期间的事件处理和可观测性。

**关键类**:
- **`BaseCallbackHandler`** (base.py)
  - 不同组件类型的 Mixins:
    - `LLMManagerMixin` - LLM 事件（new_token、end、error）
    - `ChainManagerMixin` - 链事件
    - `ToolManagerMixin` - 工具事件
    - `RetrieverManagerMixin` - 检索器事件
    - `RunManagerMixin` - 通用运行事件

- **`CallbackManager`** (manager.py)
  - 管理回调处理器
  - 在链中传播
  - 处理异步/同步上下文

**具体处理器**:
- `StdOutCallbackHandler` - 打印到标准输出
- `FileCallbackHandler` - 写入文件
- `StreamingStdOutCallbackHandler` - 将 token 流式传输到标准输出
- `UsageCallbackHandler` - 跟踪 token 使用情况

**关系**:
- 通过 `RunnableConfig` 传递
- 被所有主要组件使用
- 与 `tracers/` 集成以进行 LangSmith 集成

### 8. **tracers/** - 追踪和可观测性

**功能**: 用于调试和监控的执行追踪（LangSmith 集成）。

**关键类**:
- **`BaseTracer`** (base.py) - 基础追踪功能
- **`LangChainTracer`** (langchain.py) - LangSmith 集成
- **`Run`** (schemas.py) - 运行数据结构

**高级功能**:
- **`LogStreamCallbackHandler`** (log_stream.py)
  - `RunLog` / `RunLogPatch` - 流式运行日志
  - 实时执行监控

- **事件流** (event_stream.py)
  - `astream_events()` - 细粒度事件流
  - V1 和 V2 实现

**关系**:
- 使用 `callbacks/` 基础设施
- 与 LangSmith 集成
- 流式传输执行元数据

### 9. **documents/** - 文档处理

**功能**: 用于检索和 RAG 应用的数据结构。

**关键类**:
- **`BaseMedia`** (base.py)
  - 带有 `id` 和 `metadata` 的基类

- **`Blob`** (base.py)
  - 原始数据抽象（字节或文本）
  - 文件加载或内存数据
  - MIME 类型支持
  - 被文档加载器使用

- **`Document`** (base.py)
  - 用于检索/RAG 的文本内容
  - `page_content`: 文本
  - `metadata`: 任意元数据
  - `id`: 可选的唯一标识符

**重要区别**:
这些用于数据处理管道，**不是** LLM 聊天消息。对于对话中的多模态内容，请改用 `messages/` 内容块。

**关系**:
- 被 `retrievers.py` 和 `vectorstores/` 使用
- 由 `document_loaders/` 加载
- 与聊天消息不同

### 10. **embeddings/** - 嵌入接口

**功能**: 文本嵌入模型的接口。

**关键类**:
- **`Embeddings`** (embeddings.py)
  - `embed_documents(texts: list[str])` - 批量文档嵌入
  - `embed_query(text: str)` - 单个查询嵌入
  - 异步变体: `aembed_documents()`, `aembed_query()`
  - 查询和文档嵌入可以不同

**关系**:
- 被 `vectorstores/` 用于相似性搜索
- 被 `retrievers` 用于语义检索
- **不**继承自 `Runnable`

### 11. **vectorstores/** - 向量存储

**功能**: 用于存储和搜索嵌入向量的接口。

**关键类**:
- **`VectorStore`** (base.py)
  - `add_documents()` / `add_texts()` - 添加嵌入文档
  - `delete()` - 删除文档
  - `similarity_search()` - 查找相似文档
  - `max_marginal_relevance_search()` - MMR 搜索

- **`VectorStoreRetriever`** (base.py)
  - 将 `VectorStore` 转换为 `BaseRetriever`
  - 实现 `Runnable` 接口

- **`InMemoryVectorStore`** (in_memory.py)
  - 简单的内存实现
  - 适用于测试和演示

**关系**:
- 使用 `Embeddings` 进行向量化
- 使用 `Document` 进行存储
- 实现 `BaseRetriever` 接口

### 12. **retrievers.py** - 检索接口

**功能**: 文档检索系统的抽象接口。

**关键类**:
- **`BaseRetriever`** (retrievers.py)
  - 继承 `RunnableSerializable[str, list[Document]]`
  - `_get_relevant_documents(query: str)` - 核心检索逻辑
  - `_aget_relevant_documents()` - 异步变体
  - 比向量存储更通用（可以使用其他方法）

**关键类型**:
- `RetrieverInput` = `str`
- `RetrieverOutput` = `list[Document]`
- `RetrieverLike` = `Runnable[RetrieverInput, RetrieverOutput]`

**关系**:
- 继承自 `Runnable`
- 被 RAG 应用使用
- 通常包装 `VectorStore`
- 可以转换为 `Tool`

### 13. **stores.py** - 键值存储

**功能**: 通用键值存储接口（主要用于缓存）。

**关键类**:
- **`BaseStore[K, V]`** (stores.py)
  - `mget(keys)` - 批量获取（返回列表）
  - `mset(kv_pairs)` - 批量设置
  - `mdelete(keys)` - 批量删除
  - `yield_keys(prefix)` - 按前缀迭代键
  - 异步变体: `amget()`, `amset()`, `amdelete()`, `ayield_keys()`

**设计**:
- 仅批量操作以提高效率
- 键和值类型的泛型
- 异步/同步并行

**关系**:
- 用于缓存 LLM 响应
- 用于存储对话历史
- 独立于 `Runnable` 协议

### 14. **load/** - 序列化系统

**功能**: LangChain 对象的保存/加载功能。

**关键类**:
- **`Serializable`** (serializable.py)
  - 可序列化对象的基类
  - `is_lc_serializable()` - 选择加入序列化
  - `get_lc_namespace()` - 类标识
  - `lc_secrets` - 排除敏感数据
  - `lc_attributes` - 要序列化的其他属性

**函数**:
- **`dump()`** (dump.py) - 序列化为 JSON
- **`load()`** (load.py) - 从 JSON 反序列化
- **Reviver** - 处理跨版本的类映射

**关系**:
- 所有主要类都继承自 `Serializable`
- 启用安全持久化
- 防止序列化机密

### 15. **其他支持模块**

**agents.py**:
- `AgentAction`, `AgentFinish`, `AgentStep`
- 传统 agent 模式（新 agents 使用 `langchain` 包）

**caches.py**:
- `BaseCache` - LLM 响应缓存
- `lookup()`, `update()`, `clear()` 方法
- 异步变体
- 降低 API 成本和延迟

**chat_history.py**:
- `BaseChatMessageHistory` - 存储和检索对话历史

- 被 `RunnableWithMessageHistory` 使用

**example_selectors/**:
- `BaseExampleSelector` - 选择少样本示例
- `LengthBasedExampleSelector` - 基于长度
- `SemanticSimilarityExampleSelector` - 基于语义相似性

**outputs/**:
- `Generation` - LLM 输出
- `ChatGeneration` - 聊天模型输出
- `LLMResult` - 批量 LLM 结果
- `ChatResult` - 批量聊天结果

**rate_limiters.py**:
- API 调用的速率限制

**globals.py**:
- 全局配置（调试、详细标志）

**utils/**:
- `iter.py` - 迭代器实用程序
- `aiter.py` - 异步迭代器实用程序

- `pydantic.py` - Pydantic 助手
- `strings.py` - 字符串实用程序

## 架构模式和关系

### 继承层次结构

```
Serializable (load/serializable.py)
    ↓
Runnable[Input, Output] (runnables/base.py)
    ↓
    ├─→ BaseLanguageModel (language_models/base.py)
    │       ├─→ BaseChatModel
    │       └─→ BaseLLM
    │
    ├─→ BaseTool (tools/base.py)
    │       ├─→ StructuredTool
    │       └─→ Tool
    │
    ├─→ BasePromptTemplate (prompts/base.py)
    │       ├─→ ChatPromptTemplate
    │       └─→ PromptTemplate
    │
    ├─→ BaseOutputParser (output_parsers/base.py)
    │
    └─→ BaseRetriever (retrievers.py)
```

### 组合模式 (LCEL)

使用 `|` 运算符组合组件:

```python
chain = prompt | model | parser
# 创建: RunnableSequence([prompt, model, parser])
```

这会自动:
- 在整个链中传递 `RunnableConfig`
- 支持流式传输
- 优雅地处理错误
- 通过回调提供可观测性

### 配置传播

`RunnableConfig` 在整个链中流动:
- 标签用于过滤
- 元数据用于跟踪
- 回调用于可观测性
- 可配置字段用于运行时行为
- 递归限制以确保安全

### 数据流

```
输入 (dict)
    ↓
提示词模板 → PromptValue
    ↓
语言模型 → 消息 / 字符串
    ↓
输出解析器 → 结构化输出
```

### 模块间依赖关系

- **runnables/** ← 所有内容的基础
- **messages/** ← 被模型、提示词、工具使用
- **callbacks/** ← 被所有可运行的组件使用
- **load/** ← 所有主要类的序列化
- **utils/** ← 共享实用程序

### 异步/同步并行

所有组件同时支持同步和异步:
```python
result = chain.invoke(input)
result = await chain.ainvoke(input)
```

默认异步实现在执行器中运行同步版本，但可以覆盖本机异步以提高性能。

## 关键设计决策

1. **Runnable 作为通用接口**: 所有内容都可通过相同的接口组合
2. **Pydantic 用于验证**: 类型安全和自动验证
3. **显式异步**: 异步变体是显式的（ainvoke、astream 等）
4. **选择加入序列化**: 必须实现 `is_lc_serializable() = True`
5. **提供者无关**: 消息内容块抽象提供者差异
6. **缓存层**: 与提供者缓存（例如，提示词缓存）分离
7. **模块化设计**: 关注点清晰分离（例如，检索器 vs 向量存储）

## 类型安全设计

所有主要组件都是泛型的，提供完整的类型安全:

```python
from typing import Generic, TypeVar

Input = TypeVar('Input')
Output = TypeVar('Output')

class Runnable(Generic[Input, Output]):
    def invoke(self, input: Input) -> Output: ...

# 使用示例
chain: Runnable[dict[str, str], str] = prompt | model | parser
```

## 总结

langchain-core 提供了一个**分层架构**，包括:

1. **基础层**: Runnable 协议、配置、序列化
2. **抽象层**: 模型、消息、工具、提示词、检索器
3. **工具层**: 回调、追踪器、缓存、存储
4. **数据层**: 文档、嵌入、向量存储

该架构设计用于:
- **可组合性** (LCEL 与 `|` 运算符)
- **可观测性** (回调和追踪)
- **灵活性** (通用接口和具体实现)
- **类型安全** (全程使用 Pydantic)
- **异步支持** (并行同步/异步 API)
- **序列化** (安全持久化，无秘密泄漏)
