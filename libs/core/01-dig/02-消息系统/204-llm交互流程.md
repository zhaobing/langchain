## 一、业务逻辑概览

### 1.1 核心目标

`stream()` 方法的主要业务目标是：**将用户的输入消息发送给 LLM，并以流式方式逐步返回响应，提升用户体验**。

**关键业务价值：**
- 🚀 **实时反馈**: 用户无需等待完整响应生成，可以逐步看到输出
- 📊 **大响应友好**: 对于长文本生成，流式输出可以避免长时间等待
- 💰 **用户体验**: 类似 ChatGPT 的打字效果，提供更好的交互体验

### 1.2 核心抽象层次

```
┌─────────────────────────────────────────────────────────────┐
│  用户层 (User Layer)                                        │
│  llm.stream([message])  ← 用户调用                           │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Runnable 协议层 (Runnable Protocol Layer)                  │
│  BaseChatModel.stream()  ← 统一的流式接口                    │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  业务逻辑层 (Business Logic Layer)                           │
│  - 配置管理 (config, callbacks)                              │
│  - 消息格式化 (_format_for_tracing)                          │
│  - 流式决策 (_should_stream)                                 │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  执行层 (Execution Layer)                                    │

└─────────────────────────────────────────────────────────────┘
```

## 三、相关技术点

### 3.1 设计模式

#### 3.1.1 模板方法模式 (Template Method)

**位置**: `BaseChatModel` 类

```python
# 基类定义骨架
def stream(self, input, config, ...):
    # 1. 检查流式能力
    if not self._should_stream(...):
        yield fallback
        return

    # 2. 准备工作（基类实现）
    config = ensure_config(config)
    messages = self._convert_input(input).to_messages()

    # 3. 调用子类实现
    for chunk in self._stream(messages, ...):  ← 抽象方法
        # 4. 后处理（基类实现）
        yield process_chunk(chunk)

# 子类实现具体逻辑
def _stream(self, messages, ...):
    # 具体模型的流式实现
    yield ChatGenerationChunk(...)
```

**优点：**
- ✅ 基类提供通用流程
- ✅ 子类只需实现核心逻辑
- ✅ 统一的处理逻辑（元数据、回调等）

---

#### 3.1.2 策略模式 (Strategy Pattern)

**位置**: `_should_stream()` 方法

```python
def _should_stream(self, *, async_api, run_manager, **kwargs):
    # 策略 1: 检查方法是否实现
    if not self._is_stream_implemented():
        return False

    # 策略 2: 检查禁用标志
    if self.disable_streaming is True:
        return False

    # 策略 3: 条件禁用（tool calling）
    if self.disable_streaming == "tool_calling" and kwargs.get("tools"):
        return False

    # 策略 4: 运行时标志
    if "stream" in kwargs:
        return kwargs["stream"]

    # 策略 5: 回调检测
    return any(isinstance(h, _StreamingCallbackHandler) for h in handlers)
```

**优点：**
- ✅ 灵活的决定逻辑
- ✅ 多种策略组合
- ✅ 易于扩展新策略

---

#### 3.1.3 迭代器模式 (Iterator Pattern)

**位置**: 整个 stream() 方法

```python
def stream(...) -> Iterator[AIMessageChunk]:
    for chunk in self._stream(...):  # 内部迭代器
        processed = process_chunk(chunk)
        yield processed  # 外部迭代器
```

**优点：**
- ✅ 惰性计算（按需生成）
- ✅ 内存友好（不需要缓存全部结果）
- ✅ 支持 for-in 语法

#### 3.2.3 合并操作 (+=)

    if isinstance(merged, str) and isinstance(content, str):
